# Architecture

Entelechy separates native workload semantics, candidate programs, compiler
implementation, and experimental evidence. Version remains 0.0.1; content hashes
identify each implementation independently.

## Human and agent responsibilities

The person provides the optimization tasks, dataset, remote environment, and any
specific requirements. The external coding agent reads the CLI tutorial and
specifications, resolves those tasks against the native TraceSet, and executes
search, implementation changes, and validation. The CLI provides operations and
evidence; the agent owns decisions and edits. See the [human quick start](../README.md#quick-start-for-people)
and the [agent execution reference](AGENT_LOOP.md).

The agent can run on a local machine while experiments run in a supplied Pod or
Modal environment. Its remote tools invoke the Entelechy CLI in that environment
and retrieve feedback and artifacts. The CLI starts its evaluation worker on the
host where it is invoked; it does not submit remote jobs itself. Experiment state
remains in the remote workspace, with results copied locally for review.

## Native input ownership

Definition.reference is authoritative. Its ordered interface, constant/variable
axes and Workload data are preserved. A TraceSet is a dataset interchange format;
it is not our scheduling IR. The agent writes a candidate IR using current
compiler capabilities. Initial seeds are explicit algorithm hypotheses and must
pass runtime reference agreement.

`input.json` is generated by the tool and stores native objects plus frozen
selection/measurement policy. It is not a second user-authored workload format.
Its `input_id` is used consistently by session, candidate, evaluation and export
artifacts.
The session's `dataset/` contains selected native files and copied blobs.
Explicit input/output order is hashed because canonical object-key sorting alone
would erase positional calling conventions.

The base package loads schemas generated from a pinned upstream revision without
importing flashinfer-bench's GPU-heavy initializer. The worker validates again
with the installed upstream models and checks resolved BenchmarkConfig agreement.
Unknown or unsupported execution controls are refused.

## Compilation and runtime

A complete CLI IR stores both a `schedule` and Definition `bindings` in
`draft.ir.json`. The low-level `Schedule` represents physical execution choices;
it is one part of the submitted program. Submission validates
shape relations for the selected workloads, lowers CUDA, and emits a native
Solution. The Solution has a torch binding and ordered destination-passing entry
point. Regeneration and source/Solution hashes detect artifact drift.

GPU execution uses FlashInfer's builder registry and default reference evaluator.
Random inputs are seeded by the session seed and workload UUID. Safetensors are
loaded from frozen files and scalar values are passed unchanged. Candidate and
baseline checks use separate cloned inputs. Output sentinels and input-preservation
checks supplement upstream numerical checks.

Timing uses Entelechy's paired ABBA protocol. Native Trace metrics retain their
upstream mathematical-reference meaning; paired sample evidence separately tracks
the chosen baseline Solution. CUPTI and diagnostic CUDA events have distinct
qualification rules. This is not a claim of statistical identity with every
upstream benchmark runner configuration.

## Search and evolution

A search session has fixed input and implementation identities. Training selects
routes in predefined buckets. Selection is frozen before a single-use holdout.
Failures or missing measurements cannot be averaged away into a claimed win.
Export qualification covers selected kernel timings, not production dispatch.

Compiler changes use `evolve begin` before edits, `evolve validate`, a new trial
via `loop fork`, and `evolve compare`. The new trial reuses frozen native inputs,
baseline, benchmark policy and budget. Old session files retain historical
evidence; ordinary loop operations require the original implementation.
`loop fork` and `evolve compare` can read the historical session without executing
its candidates. Comparison precedes
holdout and is descriptive across revisions, not a paired confidence bound.

The guards assume trusted local artifacts and source edits. File hashes and
allowlists are integrity checks, not a sandbox or a proof of semantic equivalence.

## Scope and future work

Current lowering has bounded row-kernel support; query `entelechy spec ir` for
the installed capabilities. Native schema coverage is broader than compiler
coverage. Unsupported definitions can enter an experiment and
produce rejected-submission evidence for an IR/compiler extension. Static corpus
validation covers the frozen regression fixtures and the frozen session input,
and must pass after that extension before a new GPU trial. Fixtures preserve
existing behavior; the user's task determines the optimization target.

Compiler extensions should follow evidence from the user's chosen workloads.
Broader IR semantics, hardware primitives, performance analysis, or production
integration require implementation and relevant validation when that task needs them.
The public workflow is documented in [AGENT_LOOP.md](AGENT_LOOP.md).
